# Обробка файлів — демонстрації

Демонстраційні програми до заняття 11 курсу «Системне програмування»
(ВСП «Фаховий коледж інформаційних систем і технологій КНЕУ ім. Вадима Гетьмана»).

Тема заняття — **файл для програми — це потік, такий самий, як `stdout`, тільки відкриває його сама програма**: текстові й двійкові файли, `fopen` і режими відкриття, помилки відкриття, читання (`fgets`, `fscanf`), запис (`fprintf`, `fputs`), обробка файлу за схемою «прочитати — обробити — записати», типові помилки.

## Склад рішення

Рішення `Demo_Lecture_11.slnx`: шість проєктів на C, тека зі сценаріями командного рядка і тека `Файли` з даними.

| Проєкт | Файл | Розділ конспекту | Що показує |
|---|---|---|---|
| `Demo1_kinds` | `kinds.c` | 2 | ті самі три числа в текстовому (`nums.txt`, 17 байтів) і двійковому (`nums.bin`, 12 байтів) файлі; байти обох файлів |
| `Demo2_open` | `open.c` | 3 | `fopen` з довільним іменем і режимом: три помилки (`errno` 2 і 13), дескриптор 3 і `HANDLE` успішно відкритого файлу; режим `"w"` обнуляє наявний файл |
| `Demo3_read` | `read.c` | 4 | читання `marks.txt` рядками (`fgets`) і полями (`fscanf`), значення, яке повертає `fscanf` у кінці файлу; аргумент `feof` — неправильний цикл `while (!feof(f))` |
| `Demo4_write` | `write.c` | 5 | одна функція друкує звіт і на екран, і у файл `report.txt`; режим `"a"` дописує рядок у `log.txt` |
| `Demo5_filter` | `filter.c` | 6 | фільтр оцінок ≥ 60: з іменами файлів в аргументах або через `<` і `>` |
| `Demo6_pitfalls` | `pitfalls.c` | 7 | `where` — відносний шлях і поточний каталог; `slash` — `\n` і `\t` у шляху; `crash` — аварія до `fclose` |

| Сценарій | Порядок на занятті | Програма |
|---|---|---|

| `Сценарії/demo02_open.cmd` | 2 | `Demo2_open` |

Кожен проєкт показується **один раз**, у порядку номерів.

Сценарії запускають програми з `x64\Debug\`, тому **зберіть рішення в Debug**. Поточним каталогом сценарії роблять теку `Файли`: там лежить `marks.txt`, і туди програми записують свої файли.

## Тека `Файли`

У репозиторії в ній лише **`marks.txt`** — оцінки групи, вісім рядків «прізвище оцінка». Його читають `Demo3_read`, `Demo5_filter` і `Demo6_pitfalls`. Відкрийте його в Блокноті до запуску програм.

Решту файлів створюють демонстрації: `nums.txt`, `nums.bin`, `test.txt`, `report.txt`, `log.txt`, `passed.txt`, `passed2.txt`, `crash.txt`. Git їх ігнорує, їх можна вільно видаляти.

## Як відкрити у Visual Studio

**Що має бути встановлено.** Visual Studio (Community достатньо) з компонентом **«Розробка класичних застосунків на C++»** (Desktop development with C++).

**Крок 1. Відкрити рішення.** Двічі клацнути `Demo_Lecture_11.slnx` або *File → Open → Project/Solution*. У Solution Explorer з'являться шість проєктів і теки **Сценарії** та **Файли**.

> Файл рішення збережено в новому форматі `.slnx`. Якщо ваша версія Visual Studio його не відкриває, оновіть її або відкрийте потрібний `.vcxproj` напряму.

**Крок 2. Зібрати.** На панелі зверху вибрати **Debug** і **x64**, *Build → Build Solution* (Ctrl+Shift+B).

**Крок 3. Запускати.** `Ctrl+F5` — без налагоджувача, `F5` — під налагоджувачем. F5 запускає **стартовий проєкт** (у Solution Explorer він жирний). Зручніше один раз налаштувати: правою кнопкою на рішенні → *Properties* → *Startup Project* → **Current selection**.

**Аргументи командного рядка** (`Demo2_open`, `Demo3_read feof`, `Demo5_filter`, `Demo6_pitfalls`) задаються в *Properties → Configuration Properties → Debugging → Command Arguments*.

## Робочий каталог під час запуску з Visual Studio

Відносне ім'я файлу (`marks.txt`) програма шукає в **поточному каталозі**. Під час запуску з Visual Studio поточний каталог задає параметр *Properties → Configuration Properties → Debugging → Working Directory*:

| Проєкт | Working Directory | Що буде |
|---|---|---|
| `Demo1_kinds` … `Demo5_filter` | `$(SolutionDir)Файли\` (вже налаштовано) | програми знаходять `marks.txt` і пишуть файли в `Файли` — так само, як у сценаріях |
| `Demo6_pitfalls` | `$(ProjectDir)` — **типове значення, навмисно не змінене** | `marks.txt` не знайдено; це і є демонстрація розділу 7 |

Так само, як у вашому власному проєкті: якщо програма не знаходить файл даних, спершу перевірте робочий каталог.

**Як показати файл у Visual Studio.** `nums.bin` з `Demo1_kinds`: *File → Open → File…*, вибрати файл, у кнопці *Open* натиснути стрілку → *Open With… → Binary Editor*. Видно ті самі байти, що в сценарії: `07 00 00 00 40 42 0F 00 E7 FF FF FF`.

## Налаштування проєктів

Ті самі, що в демонстраціях до занять 8–10:

| Параметр (*Properties → C/C++*) | Значення | Навіщо |
|---|---|---|
| *General → Warning Level* | `/W4` | попередження рівня 4; помилки з `Demo6_pitfalls` компілюються **без** попереджень — це частина демонстрації |
| *General → Support Just My Code Debugging* | No (Debug) | без зайвого виклику на початку кожної функції |
| *Code Generation → Basic Runtime Checks* | Default (Debug) | без додаткових перевірок стека в машинному коді |
| *Command Line → Additional Options* | `/utf-8` | вихідні файли збережено в UTF-8 |

У кожному файлі перший рядок — `#define _CRT_SECURE_NO_WARNINGS`: без нього MSVC вимагає замість `fopen` і `fscanf` нестандартні функції `fopen_s` і `fscanf_s` (попередження C4996).

## Як зібрати з командного рядка

**Developer Command Prompt for VS**, з кореня репозиторію:

```

```


## Відомі граблі

**`marks.txt: No such file or directory`.** Програму запущено не з теки `Файли`. Див. «Робочий каталог» вище — і розділ 7 конспекту.

**Адреси й `HANDLE` у `Demo2_open` не збігаються з конспектом.** Так і має бути: вони змінюються від запуску до запуску. Збігається номер дескриптора — `3`.

**У `log.txt` інші дата й час.** Так і має бути: `Demo4_write` записує час запуску. Кількість рядків дорівнює кількості запусків.

**`Demo6_pitfalls crash` у Debug під налагоджувачем (F5) зупиняється на винятку *Access violation writing location 0x0000000000000000*.** Так і має бути: це і є аварія. Натисніть Shift+F5 і подивіться розмір `crash.txt` у теці проєкту — 0 байтів.

**Кирилиця в шляху друкується знаками питання.** У власних програмах — так і буде: бібліотека C перетворює шлях на кодову сторінку Windows. `Demo6_pitfalls` у перших рядках `main` вмикає UTF-8 для консолі (`SetConsoleOutputCP`, заняття 7) і для бібліотеки C (`setlocale(LC_ALL, ".UTF8")`).

**Кодування сценаріїв.** Файли `.cmd` збережено в **UTF-8 з CRLF**, перший рядок після `@echo off` — `chcp 65001 > nul`.
